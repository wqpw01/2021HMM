# Ramalhinho 2021 HMM 项目说明文档重写设计

## 1. 目标

以桌面参考项目的 `CT血管重采样项目详细说明.md/.html` 为结构、形式和详细程度
基准，重写 Ramalhinho 2021 复现项目说明。文档同时服务于第一次接触项目的读者、
算法研发、医学影像工程、复现实验执行和结果审计人员。

最终交付不是论文摘要，而是能够回答以下问题的完整工程说明：

- 项目解决什么问题，明确不解决什么问题；
- CT 图库、EUS 特征和时间戳怎样进入程序；
- JSONL 怎样转换为 `ProbePose`、`FeatureVector` 和 CBIR 数据库；
- 器官预筛选、血管单帧 CBIR、HMM/Viterbi 怎样依次执行；
- 每个参数、状态、坐标和输出字段具体是什么意思；
- 怎样安装、验证、运行、排错和审计；
- 本次正式运行实际得到了什么，不能据此声称什么。

## 3. 事实依据与优先级

内容依据按以下优先级处理：

1. 当前项目代码和测试；
2. 本次正式运行输出中的 JSONL、CSV 和 `run_metadata.json`；
3. 当前项目 README、环境文件和已有说明；
4. Ramalhinho 等 2021 论文；
5. 历史对话中的解释，仅作为定位线索，不作为最终事实来源。

若论文描述、原始 `2021.py`、本地包装项目和正式运行参数不同，必须分别标为“论文”、
“算法脚本默认值”、“本项目默认值”或“本次正式运行值”，不能合并成一个口径。

文档必须保留以下事实边界：

- 器官信息只用于预筛选 CT 候选，不进入论文血管距离公式；
- EUS 查询没有患者世界坐标位姿，输出位姿来自 CT 候选；
- 当前 HMM 输出是 `diagnostic_only`，没有真值时不能声称定位准确率或临床有效性；
- 未提供真实时间戳时使用等单位间隔，不能解释为固定帧率或真实秒数；
- `features=[]` 表示没有可用血管特征，不必然表示人工没有画血管；
- 3 帧的人工血管轮廓因 `touches_image_edge` 被跳过，其余 11 帧当前处理结果没有
  可用血管三元组。

## 4. 文档总体结构

### 4.3 总体架构与详细流程图

## 5. 写作形式

- 使用中文，第一次出现英文缩写时给出中文解释；
- 先用日常语言说明，再给对象名、字段名、公式或代码位置；
- 一段只解释一个核心判断，避免连续堆叠术语；
- 参数同时写数值、单位、作用对象、增大/减小的实际效果；
- 示例值必须标明是正式结果、真实字段样例还是纯示意值；
- 表格用于协议和对照，段落用于解释因果，流程图用于展示先后关系；
- 不把“候选相似”写成“定位正确”，不把“没有可用特征”写成“没有人工标注”；
- Markdown 目录、标题层级和锚点保持稳定。

目标篇幅约 1,400 至 1,900 行，详细程度与参考项目一致，但不通过重复文字凑篇幅。

## 6. HTML 形式

HTML 由最终 Markdown 单一事实源生成，使用参考项目的视觉结构：

- 白色正文纸张、浅灰页面背景；
- 中文字体优先；
- 绿色章节线、表头和代码块强调；
- 响应式窄屏布局；
- 打印样式；
- 固定返回顶部按钮；
- 表格横向滚动；
- Mermaid 11 浏览器渲染，加载失败时保留可读源码。

HTML 标题、目录、正文、表格和代码内容必须来自 Markdown，不维护两套独立正文。
